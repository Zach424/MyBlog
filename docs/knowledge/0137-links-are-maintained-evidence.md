# 链接只是地址，参考资料是维护过的证据

关联：[[STATUS|当前项目状态]] · [[0137-constrained-reference-lists|Iteration 0137]] · [[0136-audio-transcript-is-content|音频文字稿是正文]]

## 裸 URL 没有说明作者判断

URL 能告诉浏览器去哪里，却不能说明它为什么与正文有关、是否是官方来源、读者应该从中验证什么。可维护的参考条目至少需要三个作者事实：可独立理解的名称、稳定目标、简短用途说明。

```text
可见名称 + HTTPS/站内目标 + 作者短注
  → 同一开放 Markdown
  → 阅读索引 / 搜索 / 知识关系 / 外链库存 / 打印来源
```

目标是机器定位，名称与短注才是知识语义。

## 作者填写比远程抓取更稳定

构建时抓取远程标题、摘要或 favicon 看似省事，实际会引入 DNS、限流、登录墙、重定向、页面改版和第三方内容漂移。相同 Git 提交可能在两次构建中产生不同结果，甚至因外站短暂不可用而无法发布。

当前契约只保存作者已经审阅并愿意公开的文字。外链健康仍可由现有显式报告按需观察，但它不写回 Markdown，也不成为默认离线构建的随机输入。

## 站内与站外链接应该复用既有事实

站内 `/posts/...` 和 `/projects/...` 已经有目标、标题锚点与知识图谱校验；HTTPS 链接已经有确定性库存和受限实时检查。参考资料清单只增加组织语义，不复制两套 URL 解析器或建立书签数据库。

这形成清楚的职责边界：

1. 参考清单定义作者为什么列出资料；
2. 站内关系系统证明目标和锚点真实存在；
3. 外链库存记录公开 HTTPS 出现位置；
4. 显式网络检查提供瞬时健康证据，但不改内容事实。

## 搜索名称与短注，不搜索 URL 噪声

读者通常记得“Route Handlers 官方说明”或“项目复盘”，不会记得完整路径。搜索索引保留清单标题、可见名称和短注，删除 `[!references]` marker、分隔符和目标 URL。站内关系与外链库存仍从原 AST 读取真实 target，两种投影各自服务不同任务。

## 打印来源必须有唯一所有者

屏幕上链接可以点击，纸面上不能。参考清单在打印时显式输出每条 URL，但普通正文已有自动附加站外 URL 的规则。如果两者同时生效，同一个地址会打印两次。

因此专用参考块负责完整来源，通用外链打印伪元素在该块内关闭。显示 URL 的职责只能有一个所有者。

## 可复用判断

1. 链接目标不是完整参考资料，作者用途说明属于内容事实；
2. 可见名称应脱离上下文仍可理解，避免“点击这里”；
3. 远程元数据是变化中的观察，不应混入确定性构建；
4. 新内容结构应复用既有链接关系和库存，不创建平行数据库；
5. 搜索投影服务人类记忆，链接库存服务机器检查，两者不必包含相同文本；
6. Studio、Obsidian 和普通编辑器都应生成同一开放 Markdown；
7. 特殊 marker 必须失败关闭，不能因结构错误静默变成普通提示块；
8. 屏幕与打印需要不同来源表达，但打印 URL 只能输出一次；
9. 构建通过证明结构与内部一致性，不证明外部网站永久在线；
10. 需要 BibTeX、网页快照或团队书签时，应另立产品契约，不把轻量参考清单无限扩张。
