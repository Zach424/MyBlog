# 视频首先是发布契约，不是一个 embed 标签

关联：[[STATUS|当前项目状态]] · [[0132-constrained-local-silent-video|Iteration 0132]] · [[0131-generated-svg-is-untrusted-compiler-output|生成的 SVG 仍是不可信编译器输出]]

## `<video>` 只解决最后一米

把一个 URL 放进 `<video>` 很容易，但它没有回答：文件属于谁、是否可长期访问、是什么编码、有没有音轨、页面会下载多少字节、作者如何上传、失败如何回滚、打印时留下什么、搜索能否理解、第三方是否追踪读者。

因此完整边界应是：

```text
可移植 Markdown 声明
  → 路径/标题/说明/数量契约
  → 作者入口的快速预检
  → 仓库附件归档与原子回滚
  → 构建期真实 MP4 解析
  → 本地原生播放器
  → 移动端/打印/搜索降级
  → Git 提交、Vercel 部署与生产烟测
```

缺少其中任一步，视频都只是一个未经管理的二进制链接。

## 浏览器兼容不等于媒体身份

浏览器成功触发 `loadedmetadata`，只能证明当前浏览器愿意解码并给出时长和尺寸。它不能稳定证明：

- 容器只有一条画面轨；
- 没有音轨、字幕轨或其他附加轨；
- 编码一定是契约要求的 H.264/AVC；
- MP4 是普通单文件而不是分片表示；
- `moov` 元数据位于前部，可以 fast start。

所以浏览器预检应快速、友好、诚实；构建期解析才是发布权威。不要因为浏览器“能播”就把未知事实显示成绿色通过。

## 无声不是可访问性的捷径

有音频的视频通常需要字幕或文字稿；而静音屏幕录制仍然需要画面说明。说明必须描述关键操作和结果，而不是重复标题，例如：

```markdown
![依次打开发布面板、确认检查通过并点击发布，页面最后显示 Production ready。](/uploads/release-flow/demo.mp4 "完整发布流程")
```

标题负责识别，说明负责替代。即使视频加载失败、读者不能观看、搜索只读取文本或页面被打印，内容仍然成立。

第一版只接受无音轨素材，是为了把字幕缺口变成明确拒绝，而不是隐性欠债。未来开放音频时，字幕文件、语言、同步、文字稿、编辑器字段、归档路径和验证门必须同一轮进入。

## 本地托管是一种范围选择

仓库本地 MP4 的优点是：

- Git 提交和正文引用共享一个事实源；
- 没有第三方播放器脚本、cookie、账号或追踪；
- Obsidian、Studio、普通 Git 和 Vercel 使用同一交付链；
- URL、回滚、所有权与孤儿文件都能被构建门验证。

代价也清楚：Git 历史会增长，Vercel 承担传输，仓库不负责转码、多码率和流媒体。因此它只适合少量、短时、经过压缩的技术演示。长视频、高频更新或大量访问出现后，应重新评估对象存储/CDN，但仍保留同样的内容声明、隐私、字幕和回滚契约。

## `preload="none"` 是产品语义

它不只是性能微调，而是在表达“正文先可读，视频由读者主动请求”。配合禁止 autoplay，可以避免：

- 读者只浏览文字却下载大文件；
- 移动网络被无意消耗；
- 页面加载与媒体下载互相竞争；
- 多段演示同时开始播放或发声；
- 把富媒体存在误当成必须立即消费。

播放器仍保留 controls、playsinline 和直接文件链接；交互由浏览器原生实现，不再发送一套自定义客户端播放器。

## 作者工具和构建门要共享语义，不共享夸大的能力

Studio 自定义组件负责让语法可发现，Obsidian 发布器负责让本地附件进入既有事务。两者都产生同一行 Markdown。浏览器快速检查 ftyp、大小、时长、尺寸和摘要；Node 端解析轨道、编码、fragmented/progressive。最终判断不依赖编辑器是否在线，也不依赖作者是否使用某个入口。

这条原则可以复用到 PDF、音频、3D、数据集等二进制内容：作者入口可以不同，正式内容语法和构建权威只能有一份。

## 可复用判断

1. 先定义来源、身份、资源预算和失败恢复，再选择渲染标签；
2. 快速预检与权威校验可以分层，但证据声明必须准确；
3. 本地托管减少第三方隐私风险，同时把存储和带宽成本收回自己承担；
4. 原生控件通常比自定义播放器更小、更稳、更容易无 JavaScript 降级；
5. 标题、说明和直接链接应与媒体一起成为持久内容；
6. 音频能力不能脱离字幕/文字稿单独开放；
7. 真实二进制必须进入构建扫描、引用所有权和孤儿文件门；
8. 生产测试应验证 DOM 语义，不要依赖 HTML 属性顺序；
9. 合成渲染可以证明能力，真实媒体样本则用于证明 Range、缓存和传输；两类证据不能互相冒充；
10. 当规模超出 Git 托管边界时可以替换存储层，但不能丢掉内容契约。
