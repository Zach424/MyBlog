# 收起是呈现状态，不是隐藏内容

关联：[[STATUS|当前项目状态]] · [[0140-constrained-faq-disclosures|Iteration 0140]]

## 披露控件只改变当前屏幕布局

FAQ 的答案可以暂时收起，降低长文章的视觉密度；但答案仍是已经发布的正文。它应该继续存在于 Markdown、服务端 HTML、全文搜索、复制和打印中，也不能因为读者没有点击就不被索引。

因此本项目把“内容是否存在”和“当前是否展开”分成两层：Markdown 保存全部问答，原生 `<details>` 的 `open` 只决定屏幕上的初始呈现。

## 原生语义比自建开关更小、更可靠

`<details>/<summary>` 已提供鼠标和键盘开合语义。第一版无需 React state、按钮事件、localStorage、cookie 或数据库。首题使用 `open` 提供答案密度样本，其余问题保持收起；读者之后的开合只存在于当前文档实例。

原生元素并不免除验证责任：仍需检查可见焦点、窄屏换行、减少动态效果偏好和打印表现。打印尤其要强制显示关闭条目的答案，否则屏幕上的临时状态会意外污染静态文档输出。

## FAQ 与 Callout 不是同一种内容

两者都能使用块引用 marker，也都可能折叠，但含义不同：

- Callout 是单个提示或警告，可包含一般块级内容；
- FAQ 是多个可独立查询的问题，每项必须具有问题与答案关系；
- FAQ 的预算、问题去重、搜索投影和原生 details 结构都不同于 Callout。

因此 `[!faq]` 候选必须由专用校验器先处理。若结构错误，应失败关闭，不能悄悄变成普通 Callout。

## 搜索与打印需要完整事实

搜索应删除 `[!faq]` 这类作者协议噪声，保留标题、问题与每段答案。打印应展开所有答案并隐藏加号。这样无论读者通过站内搜索、浏览器打印还是源文阅读进入，看到的都是同一份内容事实。

## 可复用判断

1. 折叠只能改变视图，不能改变内容事实；
2. 优先使用 `<details>/<summary>`，只有任务确实需要跨访问状态时才引入持久化；
3. 首题默认展开是内容预览，不是永久状态；
4. 原生交互仍需验证焦点、键盘、减少动态效果、窄屏和打印；
5. FAQ 与 Callout 应有独立契约和转换优先级；
6. 搜索保留问题与答案，只删除 marker 和视觉标签；
7. CMS 组件应生成开放 Markdown，不成为第二事实源；
8. 规范化去重只证明文本身份，不推断问题语义；
9. 合成预览证明渲染能力，不证明答案准确；
10. 只有需要投票、评论、协作或远程检索时，才建立独立问答系统契约。
