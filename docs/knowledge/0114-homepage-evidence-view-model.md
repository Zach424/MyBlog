# 用内容事实生成首页证据

关联：[[STATUS|当前项目状态]] · [[0114-content-derived-homepage-evidence|Iteration 0114]]

## 问题

“正在构建什么”“最近学到什么”“当前关注什么”看起来只是文案，但它们实际指向项目和文章。如果组件直接保存摘要，新内容发布或项目状态变化后，首页会继续展示旧判断。

## 投影边界

本轮把内容记录转换为一个首页专用 view-model：

```text
精选 ProjectRecord ──→ Building 标题 / 状态 / stack 摘要
最新 PostRecord ─────→ Learned 标题 / 类型 / 日期 / tag 摘要
公开路由最新日期 ────→ Current focus 日期
                         ↓
                createHomepageEvidence()
                         ↓
                 首页只负责语义渲染
```

view-model 使用 TypeScript `Pick` 只接收真正需要的字段，不让正文、源路径或其他作者数据进入首页模块。

## 密度策略

- 项目标题和文章标题完整保留，由 CSS 自然换行；
- stack 显示前 2 项，其余显示 `+N`；
- tag 显示第 1 项，其余显示 `+N`；
- 项目状态翻译为规划中、构建中、持续维护、已归档；
- 内容类型保持 ARTICLE/TIL 机器感，同时 Current focus 使用中文“最新文章”或 TIL；
- Current focus 只组合已存在的状态、类型和日期，不创建新的作者字段。

## 空集合规则

```text
无项目 → 等待首个公开项目 / PROJECT · NO PUBLIC RECORD
无文章 → 等待首篇学习记录 / POST · NO PUBLIC RECORD
全空   → 等待第一条公开记录
```

空状态必须由同一纯函数生成，不能在 React 组件里另写一套兜底。这样夹具能直接验证，也避免空库显示看似真实但没有来源的运行状态。

## 测试层次

1. 纯函数精确比较真实长标题、状态翻译、列表摘要和 Current focus；
2. 空集合测试证明不发明项目、文章或日期；
3. 非负整数门拒绝无效公开路由计数；
4. SSR 测试验证最终 HTML 并拒绝旧静态句子；
5. 390×844 深色浏览器检查完整标题、一个 H1 和零横向溢出；
6. HTML raw/gzip 预算确认真实内容投影没有扩大传输风险。

## 可复用经验

UI 中的“状态”可分两类：长期承诺可以是稳定文案，随业务对象变化的状态必须从对象投影。专用 view-model 能把状态翻译、摘要密度和空值策略从组件中移出，同时不污染领域模型，也不要求客户端重新取数。

判断一个字段是否应该数据驱动，可以问：如果文章、项目或部署事实变化，这句话是否应该自动变化？如果答案是“是”，它就不应只存在于 JSX 字符串里。
